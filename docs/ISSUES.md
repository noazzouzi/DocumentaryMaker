# Contract issues and requests (append-only)

Agents never edit `packages/core/**`, `package.json` files, the lockfile or root configs. When the contract blocks you, add an entry here (newest last) and work around it locally inside your package. The integration agent (I) applies accepted changes after P1 and records them in `docs/CONTRACT-CHANGES.md`.

Template:

```
## <YYYY-MM-DD> <pkg> → <target file or package>
**Problem.** What blocks you (one paragraph, with the failing call or type).
**Proposed diff.** The exact change (code block).
**Local workaround.** What you did in your package meanwhile.
```

## 2026-10-02 F → (notes from the P0 foundation; for I and every agent)

Deviations from the spec made in P0, and things later phases must know. None blocks P1.

1. **`@docmaker/engine` depends on `zod@4.6.5`.** Its §4.19 API (`readDoc`/`writeDoc`, `StageDef`) imports `type { z } from "zod"`; pnpm does not hoist zod, so the package could not type-check without the dependency. Added by F (also listed in `docs/CONTRACT-CHANGES.md`).
2. **`findRepoRoot` / `loadRuntime` throw `VALIDATION`** when no `pnpm-workspace.yaml` is found: `ErrorCode` has no `CONFIG` code (the signature sheet says "Throws CONFIG").
3. **CLI shim.** `apps/cli/bin/docmaker.js` uses `#!/usr/bin/env node` and registers tsx in-process (`tsx/esm/api`) instead of the spec's `#!/usr/bin/env -S node --import tsx`: Node resolves `--import tsx` from the current working directory, so the spec'd shim fails outside the repo. The proxy re-exec (`NODE_USE_ENV_PROXY=1`) is kept and also passes `--disable-warning=UNDICI-EHPA`.
4. **No telemetry, no generated agent files.** The root `build`/`typecheck` scripts prefix `TURBO_TELEMETRY_DISABLED=1`; the web `dev`/`build`/`start` scripts prefix `NEXT_TELEMETRY_DISABLED=1` (POSIX syntax; Windows is WSL-only per §1.4). `turbo.json` adds `"agentGuidance": false`, otherwise turbo writes an `AGENTS.md` at the repo root whenever an AI agent runs it.
5. **`measureEbur128`** runs `ebur128=peak=sample+true:framelog=quiet` (the spec says `peak=true`) so `samplePeakDbfs` is real; `-inf` values are clamped to −144.
6. **`twoPassLoudnorm` and pure tones.** ffmpeg only enables linear mode when the measured LRA ≠ 0; a pure sine is always "dynamic" (then reported as such). Use level-varying test signals (W4, W5).
7. **`defaultProject().captions` is `"burn"`** (drama-commentary's `captionDNA.defaultMode`): `defaultProject` has no style input. The engine should re-apply the chosen style's `captionDNA.defaultMode` when the style is confirmed (W10).
8. **`HomePaths.music` = `<home>/music/procedural`** (literal reading of the interface comment). Library music is never copied there.
9. **`ProjectStore` error codes:** `create` on an existing project → `VALIDATION`; `open` of a missing project → `UPSTREAM_MISSING`; reading a missing document → `UPSTREAM_MISSING`; unsupported `formatVersion` → `MIGRATION_FAILED`. `writeJson` validates with the caller's schema **and** the `DOC_REGISTRY` schema. History files are `.history/<rel>/<iso with ':'→'-'>-<etag8>.json`; `history()` returns project-relative paths, newest first.
10. **Extra exports beyond the signature sheets** (additive, safe to use): core/node `parseEnvFile`, `homePaths`, `DEFAULT_RENDER_LOCK`, `sha256Bytes`, `parseEbur128Summary`, `tryAcquireLock`, `releaseLock`, `REDACTED`, type `WavFormat`; core/testing `makeScenario`, `planKeyOf`, `TEST_NOW`, `TEST_SLUG`, `TEST_SEED`, and `makeBeats(script, { cues, revealIn })` (extra optional `revealIn`). `makeTimeline` is built from `makeScenario` with `withClip/withBreath/withReveal = false`.
11. **Async stubs throw synchronously.** The §4.19 stubs are `function f(): Promise<X> { throw notImplemented(...) }`, so `f().catch()` throws before returning a promise. Wrap calls in `try`/`await` (W10 fakes replace them anyway).
12. **Root `vitest.config.ts` is literal:** the `render-int` and `e2e` projects have no `passWithNoTests`, so `pnpm test:render` / `pnpm test:e2e` exit 1 with "No test files found" until W7/W8/W10 add tests.
13. **Remotion props typing.** `Composition` requires `Record<string, unknown>` props; `Root.tsx` registers a wrapper typed `Pick<DocProps, keyof DocProps>` (same shape as the verbatim `DocProps` interface).
14. **`apps/web/tsconfig.json`** does not include `next-env.d.ts` (it is generated by `next build`, gitignored, and imports `.next/types`): typecheck results never depend on a previous build.
15. **`@remotion/eslint-plugin@4.0.532`** declares an ESLint ≤ 8 peer (via an old `@typescript-eslint/utils`); it loads and runs fine under ESLint 10 (`pnpm lint` passes).
16. **`claude-opus-5-5`** appears in the verified contract (`Project.llm.model` literal, `PRICES`): kept verbatim.

## 2026-10-02 styles (W1) → §4.19 styles stub comments, W7 (rail captions), W10/W11 (consumers)

Notes and clarifications from `@docmaker/styles`; no contract change is required to use the package.

**Problem.**
1. `scaffoldStyle({ destDir })` is ambiguous in the stub ("copies the base dir to <home>/styles/<id>"). Implemented as: `destDir` is the user styles **root** (`HomePaths.styles`); the style is created at `<destDir>/<newId>` and that absolute path is returned. Never overwrites (existing dir or id → `VALIDATION`).
2. `discoverStyles` must not let one broken user style take the app down. Built-in defects throw; an invalid user style dir is **skipped** and reported in a new optional, additive `StyleRegistry.rejected?: { dir, issues: LintIssue[] }[]` (for the `/styles` gallery and `docmaker style validate`). Duplicate ids still throw `VALIDATION` as specified.
3. `true-crime-dossier` uses the `rail` caption variant, but §10.8's "rail at y ≈ 980" would overlap the style's bottom-12 % keep-out (`validateStyleData` error `STYLE_CAPTION_KEEPOUT`). The preset's `captionBand` is `{x:360, y:880, w:1200, h:64}`; W7's rail renderer should position the rail inside `tokens.layout.zones.captionBand`, not at a hard-coded y. Its mono caption weight is 700 (JetBrains Mono ships 400/700 only; §10.8 says 600).
4. `cinematic-essay` sets `grade.letterbox: 2.39`; all its text zones are kept inside the picture area (bars ≈ 138 px), which a test enforces. `ThemeOverride` has no letterbox switch, so a project cannot turn the bars off without a scaffolded variant style.
5. Loaded `StylePlugin` objects are deep-frozen (shared across stages); consumers must copy before merging overrides (`{...tokens, ...}` is fine, in-place mutation throws in strict mode).

**Proposed diff.** Stub comments only (for I, when convenient):
```ts
/** `docmaker style new <id> --from <base>`: copies the base dir to <destDir>/<newId> (destDir = HomePaths.styles), rewrites manifest.id/names; returns the new dir. */
export interface StyleRegistry { /* … */ readonly rejected?: readonly { dir: string; issues: LintIssue[] }[] }
```

**Local workaround.** Implemented as described; additive exports: `inspectStyleDir` (non-throwing lint of a dir, for `style validate`), `lintPromptPack`, `riskFlagsOffline`, `styleFontAssets` (asset-server paths `styles/<dir>/fonts/<file>` for user style fonts → `StyleRenderTokens.fonts`), `createRegistry`, `STYLE_RULES`.
